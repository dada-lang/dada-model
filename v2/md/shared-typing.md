# Shared: typing and soundness

## When a give copies

````{example} shared.typing.example.copy
:status: draft
:uses: shared.example.copy_field given.typing.views

The type of a place tells us whether giving it moves or copies. Consider a box
whose field has type `Token`:

```dada
class Token {}
class Box { item: Token }

let b = new Box(new Token());
let s = b→share;
let u = s.item→;
let v = s.item→;
```

| Statement | Result type | Effect on the source |
| --- | --- | --- |
| Construct `b` | `Box` | — |
| Give-share `b` | `shared Box` | `b` becomes empty. |
| Give `s.item` into `u` | `shared Token` | The field stays initialized. |
| Give `s.item` into `v` | `shared Token` | The field stays initialized. |

The field is declared `Token`, but access through `s` makes its effective type
`shared Token`. The first field give changes its stored reference to shared and
returns a shared copy; the second copies it again. Neither changes `s`'s type.

This chapter adds two permissions, `given` and `shared`, to Given's types and
views. `Token` is shorthand for `given Token`. It also carries Given's
unpacking patterns into Shared, with unpacking restricted to unique results.
````

## Permissions and field declarations

```{definition} shared.typing.types
:status: draft
:uses: given.typing.views given.typing.normalization shared.state

A *permission* \\(\pi\\) describes unique or shared access. A *nominal type*
\\(N\\) pairs a class name \\(C\\) with a signed view \\(A\\), as in Given.
A *type* \\(T\\) may apply a permission to another type:

\\[
\begin{aligned}
\pi &::= \mathsf{given}\mid\mathsf{shared},\\
N &::= C.A,\\
T &::= N\mid\pi\,T.
\end{aligned}
\\]

Bare \\(C\\) still abbreviates \\(C.\{\epsilon\}\\). Positive view entries
expose initialized subtrees; negative entries describe empty slots; omitted
branches are unknown and inaccessible. Views do not assign ownership modes
to objects.

Write \\(\pi\pi'\\) for permission composition:

| Outer permission | Inner `given` | Inner `shared` |
| --- | --- | --- |
| `given` | `given` | `shared` |
| `shared` | `shared` | `shared` |

Types are identified by:

\\[
\mathsf{given}\ T=T,
\qquad
\pi(\pi'T)=(\pi\pi')T.
\\]

Thus `shared shared Token` is `shared Token`. A normalized type has one outer
permission and a normalized nominal view: \\(\pi\,C.A\\). We omit `given`
when printing it. Write \\(\operatorname{perm}(T)=\pi\\) and
\\(\operatorname{base}(T)=C\\).

The runtime mode corresponding to `given` is `unique`; that corresponding to
`shared` is `shared`. Write \\(\operatorname{mode}(\pi)\\) for this mapping.
```

```{definition} shared.typing.declarations
:status: draft
:uses: shared.typing.types given.typing.declarations

A *typed class table* \\(\Sigma\\) gives each field a permission and a class.
Constructor arguments must supply whole values of the declared types:

\\[
\begin{aligned}
F &::= \pi\,C,\\
d &::= \mathsf{class}\ C\ \{f_1:F_1,\ldots,f_n:F_n\},\\
\Sigma &\in \mathsf{ClassName}\rightharpoonup
  \mathsf{List}(\mathsf{FieldName}\times F).
\end{aligned}
\\]

Here \\(F\\) also denotes the set of field types generated by its grammar.
Class names are distinct, field names within a class are distinct, and every
referenced class is declared. Erasing field types produces the operational
class table \\(\lfloor\Sigma\rfloor\\), preserving field order.

Given's view operations use the class component of each declaration. Valid
relative paths, positive and negative observations, normalization, nominal
focusing, and emptying are otherwise unchanged. A positive entry exposes a
whole declared subtree, including any shared fields in it. Moving a field can
still leave its slot empty.

A type is well formed when its base class is declared and its view is well
formed under these class components, including Given's nonoverlap condition.
```

## Following a path

````{example} shared.typing.example.paths
:status: draft
:uses: shared.typing.declarations shared.resolution

A shared link may occur anywhere along a path:

```dada
class Token {}
class Box { item: Token }
class Outer { box: shared Box }
class Holder { item: shared Token }
```

Consider initialized variables `b: Box`, `s: shared Box`, `o: Outer`, and
`h: Holder`:

| Place | Effective type | Giving it |
| --- | --- | --- |
| `b.item` | `Token` | Moves the token. |
| `s.item` | `shared Token` | Copies a shared reference. |
| `o.box.item` | `shared Token` | Copies a shared reference. |
| `h.item` | `shared Token` | Copies a shared reference. |

In the third row, `o` is unique but its `box` field is shared. In the fourth,
the final field itself is declared shared. A unique container can therefore
contain a field that is copied when given.
````

```{definition} shared.typing.focus
:status: draft
:uses: shared.typing.declarations given.typing.focus shared.typing.example.paths

To find a field's effective type, carry the permission of the enclosing path
into the field. Access to a field declared \\(F\\) through a whole value of
type \\(\pi\,C\\) has type \\(\pi F\\).

For a relative path \\(\rho\\), define its *declared permission*
\\(\operatorname{decl}_{\Sigma}(C,\rho)\\) by composing its field permissions:

\\[
\begin{aligned}
\operatorname{decl}_{\Sigma}(C,\epsilon)&=\mathsf{given},\\
\operatorname{decl}_{\Sigma}(C,f\rho)&=
  \pi_f\operatorname{decl}_{\Sigma}(D,\rho)
  &&\text{where }(f:\pi_f D)\in\Sigma(C).
\end{aligned}
\\]

It is defined exactly on paths valid from \\(C\\). Extend Given's focusing
operation to \\(T=\pi N\\), where \\(N=C.A\\):

\\[
T\downarrow\rho
=\bigl(\pi\operatorname{decl}_{\Sigma}(C,\rho)\bigr)
  (N\downarrow\rho),
\qquad \rho\in\operatorname{pos}_{\Sigma}(N).
\\]

Here \\(N\downarrow\rho\\) is Given's nominal focus, using the class
components of \\(\Sigma\\). It preserves the field's current view, including
holes. The new operation \\(T\downarrow\rho\\) adds the effective permission
and normalizes the result. It does not restore moved or hidden fields. The
positive and negative observations of \\(T\\) are those of \\(N\\).
```

```{definition} shared.typing.giving
:status: draft
:uses: shared.typing.focus given.typing.environments given.typing.emptying

A *slot description* \\(B\\) is either \\(0\\), for an empty variable, or
a type. A *typing environment* \\(\Gamma\\) describes every variable slot:

\\[
B::=0\mid T,
\qquad
\Gamma\in\mathsf{VariableId}\rightharpoonup B.
\\]

Types must be well formed and normalized. Empty variables remain in the domain
and cannot be reused as fresh names.

Write a place as \\(p=x.\rho\\): for `o.box.item`, the root variable is `o`
and the relative path is `box.item`; for `o`, the relative path is
\\(\epsilon\\). Define \\(\mathsf{give}_{\Sigma}(\Gamma,p)=(T,\Gamma')\\)
when \\(\Gamma(x)=U\\), the path is positive in \\(U\\), and:

\\[
T=U\downarrow\rho,
\qquad
\Gamma'=\begin{cases}
\Gamma & \operatorname{perm}(T)=\mathsf{shared},\\
\Gamma[x\mapsto0] & \operatorname{perm}(T)=\mathsf{given},\ \rho=\epsilon,\\
\Gamma[x\mapsto U[-\rho]] & \operatorname{perm}(T)=\mathsf{given},\ \rho\ne\epsilon.
\end{cases}
\\]

In the last case, empty the nominal view as in Given and retain the outer
permission. A given result requires every permission along its route to be
given. A shared result leaves the entire environment unchanged.
An absent variable, an empty source, or an inaccessible field makes this static
give operation undefined. A field hidden by a view may still hold a value at runtime.
```

```{definition} shared.typing.weakening
:status: draft
:uses: shared.typing.types given.typing.forgetting

View weakening can hide initialization facts while preserving the permission.
For normalized \\(T=\pi C.A\\) and \\(U=\pi'C'.A'\\), define:

\\[
T\preceq_{\Sigma}U
\iff
\begin{gathered}
\pi=\pi'\ \land\ C=C'\\
{}\land\ \operatorname{pos}_{\Sigma}(U)\subseteq\operatorname{pos}_{\Sigma}(T)\\
{}\land\ \operatorname{neg}_{\Sigma}(U)\subseteq\operatorname{neg}_{\Sigma}(T).
\end{gathered}
\\]

For example, `shared Box` can be weakened to `shared Box.{}`. There is no
weakening from `Box` to `shared Box`: creating a shared reference requires the
runtime give-share operation. Different aliases may expose different views
of the same object.
```

## Typing expressions

```{definition} shared.typing.expressions
:status: draft
:uses: shared.typing.giving shared.typing.weakening shared.typing.declarations shared.syntax

*Expression typing* \\(\Sigma;\Gamma\vdash e:T\;\triangleright\;\Gamma'\\)
records the result's type and the variable descriptions after evaluation.
All type expressions in the rules are normalized using the permission equations
and view normalization.
Giving uses the effective path type. Give-share first gives, then applies
`shared` to the result:

\\[
\frac{\mathsf{give}_{\Sigma}(\Gamma,p)=(T,\Gamma')}
{\Sigma;\Gamma\vdash p\mathord{\to}:T\;\triangleright\;\Gamma'}
\quad\text{Give}
\\]

\\[
\frac{\mathsf{give}_{\Sigma}(\Gamma,p)=(T,\Gamma')}
{\Sigma;\Gamma\vdash p\mathord{\to}\mathsf{share}:\mathsf{shared}\ T
  \;\triangleright\;\Gamma'}
\quad\text{Give-share}
\\]

Both rules make the same change to the source. Give-share preserves the result's
view: it changes permission, not initialization.

**Construct** checks arguments from left to right against the declared field
types. The new object's reference is given, even when some fields are shared:

\\[
\frac{
\begin{gathered}
\Sigma(C)=[f_1:F_1,\ldots,f_n:F_n]\\
\Sigma;\Gamma_{i-1}\vdash e_i:F_i\;\triangleright\;\Gamma_i
  \quad(1\le i\le n)
\end{gathered}
}{
\Sigma;\Gamma_0\vdash\mathsf{new}\ C(e_1,\ldots,e_n):C
  \;\triangleright\;\Gamma_n
}
\quad\text{Construct}
\\]

The argument count must match the declaration. With no arguments, the
environment is unchanged. Arguments still require their whole declared types.
A result may expose a weaker view:

\\[
\frac{\Sigma;\Gamma\vdash e:T\;\triangleright\;\Gamma'
  \qquad T\preceq_{\Sigma}U}
{\Sigma;\Gamma\vdash e:U\;\triangleright\;\Gamma'}
\quad\text{Weaken}
\\]
```

````{example} shared.typing.example.arguments
:status: draft
:uses: shared.typing.example.paths shared.typing.expressions

With `Token`, `Box`, and `Holder` declared above:

```dada
let t = new Token();
let h = new Holder(t→share);
let a = h.item→;
let b = h.item→;
```

The constructor requires a `shared Token`, so its argument explicitly shares
the token. Afterwards `t` is empty, `h: Holder`, and both `a` and `b` have
type `shared Token`. Giving `h.item` does not empty it.

Replacing the constructor argument with `t→` is rejected: its type is `Token`,
not the declared `shared Token`. Conversely, `new Box(a→)` is rejected because
the shared result cannot supply the given `Token` required by `Box`.
````

````{example} shared.typing.example.partial
:status: draft
:uses: shared.typing.expressions given.typing.example.views

Sharing also preserves a partially moved value:

```dada
class Token {}
class Pair { left: Token, right: Token }

let p = new Pair(new Token(), new Token());
let t = p.left→;
let s = p→share;
let a = s.right→;
let b = s.right→;
```

Moving `left` leaves `p: Pair.{-left, right}`. Give-share then empties `p` and
produces `s: shared Pair.{-left, right}`. The last two statements produce
shared tokens and preserve that view of `s`.

Giving `s.left→` is rejected because `left` is empty. Weakening `s`'s view
could hide that fact, but could not make the field accessible again.
````

## Binding results

```{definition} shared.typing.patterns
:status: draft
:uses: given.patterns given.unpacking shared.steps shared.state

An unpacking pattern consumes a uniquely owned container and transfers its
field slots to fresh variables. This extends Shared's statements with Given's
flat *binding patterns* \\(b\\):

\\[
\begin{aligned}
b&::=x\mid C\mathord{\to}\{f_1:x_1,\ldots,f_n:x_n\},\\
t&::=\mathsf{let}\ b=e.
\end{aligned}
\\]

Each declared field must appear exactly once; destination variables are distinct
and fresh in the variable table after expression evaluation. Field order in the
pattern is immaterial. `f` abbreviates `f: f`;
there are no `_` or `..` patterns here.

Write \\(\Delta\vdash\langle S,e\rangle\Downarrow\langle S',r\rangle\\)
for Shared's expression evaluation. It is unchanged. A *configuration*
\\(K=\langle S,P\rangle\\) pairs storage with the remaining statement sequence.
The extended statement
relation \\(\Delta\vdash K\longrightarrow_u K'\\) first evaluates the
expression, then binds its result:

- A variable pattern stores the reference, of either mode, in its fresh slot.
- A `C → { ... }` pattern requires \\(r=(\mathsf{unique},\alpha)\\) and
  an allocated `C` object at \\(\alpha\\). Transfer every field slot to its
  named destination and remove \\(\alpha\\) from the object table.

Field references retain their modes and targets; empty fields become empty
variables. All other storage and the allocation counter remain as in
\\(S'\\). The statement is removed from the remaining sequence. A shared
result has no unpacking transition: consuming its container would invalidate
other owners. This is an extension of the preceding chapter's machine.
```

```{definition} shared.typing.bindings
:status: draft
:uses: shared.typing.patterns shared.typing.giving shared.typing.focus

*Binding typing* \\(\Sigma;\Gamma\vdash b:T\Rightarrow\Gamma'\\) describes
where a result goes. A fresh variable receives its type unchanged:

\\[
\frac{x\notin\operatorname{dom}(\Gamma)}
{\Sigma;\Gamma\vdash x:T\Rightarrow\Gamma[x\mapsto T]}
\quad\text{Bind}
\\]

For unpacking, the container must be given and every direct field's status
must be known. Define its field descriptions by:

\\[
\mathsf{field}_{\Sigma}(T,f)=\begin{cases}
0&f\in\operatorname{neg}_{\Sigma}(T),\\
T\downarrow f&f\in\operatorname{pos}_{\Sigma}(T).
\end{cases}
\\]

An unknown field has no description. Unpacking transfers these descriptions:

\\[
\frac{
\begin{gathered}
\operatorname{perm}(T)=\mathsf{given}
\qquad\operatorname{base}(T)=C
\qquad\Sigma(C)=[f_1:F_1,\ldots,f_n:F_n]\\
\mathsf{field}_{\Sigma}(T,f_i)=B_i\quad(1\le i\le n)\\
x_1,\ldots,x_n\text{ distinct and absent from }\operatorname{dom}(\Gamma)
\end{gathered}
}{
\Sigma;\Gamma\vdash C\mathord{\to}\{f_1:x_1,\ldots,f_n:x_n\}:T
  \Rightarrow\Gamma[x_1\mapsto B_1,\ldots,x_n\mapsto B_n]
}
\quad\text{Unpack}
\\]

The displayed fields are ordered as declared. A transferred field can be
shared even though the container must be given. As in Given, a field's
interior may have a partial view; only its direct slot status must be known.
```

````{example} shared.typing.example.unpack
:status: draft
:uses: shared.typing.bindings shared.typing.example.arguments

Continuing the `Holder` example:

```dada
let Holder → { item } = h→;
let c = item→;
```

The first statement empties `h`, consumes the holder, and binds
`item: shared Token`. The aliases `a` and `b` still own the token. The second
copies it again, leaving `item` initialized.

If `s: shared Holder`, the pattern `let Holder → { item } = s→` is rejected.
The result is shared even if this happens to be the only reference to that
holder. A type grants the access its permission describes; it does not count
aliases to recover unique ownership.
````

```{definition} shared.typing.statements
:status: draft
:uses: shared.typing.expressions shared.typing.bindings given.typing.statements

*Statement typing* and *statement-sequence typing* thread the environment
through expression evaluation and binding:

\\[
\frac{\Sigma;\Gamma\vdash e:T\;\triangleright\;\Gamma_1
  \qquad\Sigma;\Gamma_1\vdash b:T\Rightarrow\Gamma_2}
{\Sigma;\Gamma\vdash\mathsf{let}\ b=e\Rightarrow\Gamma_2}
\quad\text{Let}
\\]

\\[
\frac{}{\Sigma;\Gamma\vdash[]\Rightarrow\Gamma}
\qquad
\frac{\Sigma;\Gamma\vdash t\Rightarrow\Gamma_1
  \qquad\Sigma;\Gamma_1\vdash P\Rightarrow\Gamma_f}
{\Sigma;\Gamma\vdash t::P\Rightarrow\Gamma_f}.
\\]

Here \\(P\\) is the remaining ordered sequence of statements. A program is
well typed when \\(\Sigma\\) is well formed and its statements typecheck
from the empty environment. As in Given, completion retains the final storage;
the final environment need not be empty.
```

## Relating types to storage

```{definition} shared.typing.realization
:status: draft
:uses: shared.typing.focus shared.typing.giving shared.well_formed shared.resolution given.typing.realization

A reference's type describes access from that reference. It does not prescribe
one view for the object independent of its aliases.

For \\(r=(\kappa,\alpha)\\), follow a relative path \\(\rho\\) from
\\(\alpha\\), accumulating reference modes starting with \\(\kappa\\),
as in {anchor-ref}`shared.resolution`. The empty path returns \\(r\\).
A missing object or field, or an empty intermediate slot, makes traversal
undefined; a final slot may be empty.

Write \\(\Sigma;S\models r:T\\), for normalized \\(T=\pi C.A\\), when:

1. The root reference has mode \\(\operatorname{mode}(\pi)\\) and targets
   an allocated object of class \\(C\\).
2. Every \\(\rho\in\operatorname{pos}_{\Sigma}(T)\\) reaches an allocated
   object of its declared class. Every \\(\rho\in\operatorname{neg}_{\Sigma}(T)\\)
   reaches an existing empty slot.
3. Every valid finite path from \\(C\\) that reaches an occupied slot from
   this root, including paths hidden by the view,
   has effective mode
   \\(\operatorname{mode}(\pi\operatorname{decl}_{\Sigma}(C,\rho))\\).

The third condition concerns the whole route. A field declared given inside a
shared container may store a unique reference before copying and a shared one
afterwards. Both routes have effective shared mode.

Let \\(R\\) be an ordered list of *pending values* \\((r:T)\\), for expression
results not yet stored by a binding or constructor. Define
\\(\Sigma;\Gamma\models(S;R)\\), where \\(S=\langle O,V,\nu\rangle\\), by:

- Structural well-formedness holds as in {anchor-ref}`shared.well_formed`,
  counting pending references alongside all stored owning occurrences.
- Every occupied field targets an object of its declared class, including
  fields hidden by views.
- \\(\operatorname{dom}(\Gamma)=\operatorname{dom}(V)\\). A description
  \\(\Gamma(x)=0\\) means \\(V(x)=\bot\\); a description \\(\Gamma(x)=T\\)
  means \\(V(x)=r\\) with \\(\Sigma;S\models r:T\\).
- Every pending pair \\((r:T)\\) satisfies \\(\Sigma;S\models r:T\\).

The table \\(\Sigma\\) and all types must be well formed. Shared aliases
may carry different views; each must describe the actual storage. Hidden
references still contribute to ownership and liveness.
```

```{lemma} shared.typing.expression_soundness
:status: draft
:uses: shared.typing.realization shared.typing.expressions shared.typing.patterns

For any well-formed \\(\Sigma\\), if

\\[
\Sigma;\Gamma\vdash e:T\;\triangleright\;\Gamma',
\qquad\Sigma;\Gamma\models(S;R),
\\]

then an evaluation exists:

\\[
\exists S',r.\;
\lfloor\Sigma\rfloor\vdash\langle S,e\rangle\Downarrow\langle S',r\rangle.
\\]

Every such evaluation satisfies
\\(\Sigma;\Gamma'\models(S';R\mathbin{+\!\!+}[(r:T)])\\), where
\\(+\!\!+\\) appends lists. This includes arbitrary pending results of
earlier constructor arguments. A copy preserves existing aliases' views;
a move preserves the types of the other owning roots.
```

```{definition} shared.typing.configurations
:status: draft
:uses: shared.typing.realization shared.typing.statements shared.typing.patterns

A configuration \\(K=\langle S,P\rangle\\) is well typed with final
environment \\(\Gamma_f\\) when:

\\[
\Sigma\vdash\langle S,P\rangle:\Gamma_f
\iff
\exists\Gamma.\;
  \Sigma;\Gamma\models(S;[])
  \land\Sigma;\Gamma\vdash P\Rightarrow\Gamma_f.
\\]

This requires a well-formed \\(\Sigma\\). Write
\\(\longrightarrow_u^{*}\\) for zero or more extended statement steps.
A configuration is finished when \\(P=[]\\), and stuck when statements
remain but no extended step is possible.
```

## Progress and preservation

```{theorem} shared.typing.progress
:status: draft
:uses: shared.typing.configurations shared.typing.expression_soundness shared.typing.bindings

A well-typed configuration has finished or can take a step:

\\[
\Sigma\vdash K:\Gamma_f
\quad\Longrightarrow\quad
\mathsf{Finished}(K)\ \lor\
\exists K'.\;\lfloor\Sigma\rfloor\vdash K\longrightarrow_u K'.
\\]
```

```{theorem} shared.typing.preservation
:status: draft
:uses: shared.typing.configurations shared.typing.expression_soundness shared.typing.bindings

Every step from a well-typed configuration preserves its final typing:

\\[
\frac{\Sigma\vdash K:\Gamma_f
  \qquad\lfloor\Sigma\rfloor\vdash K\longrightarrow_u K'}
{\Sigma\vdash K':\Gamma_f}.
\\]

The current environment changes when a source is moved or a result is bound.
A shared give itself preserves the environment even when the final stored
reference changes mode; binding its result then adds a fresh variable.
```

```{theorem} shared.typing.safety
:status: draft
:uses: shared.typing.progress shared.typing.preservation shared.typing.statements

A well-typed program, started with empty storage, cannot reach a stuck
configuration. Every finite execution can be extended to a finished one whose
total step count equals the initial number of statements. This includes
copying, give-share, and unpacking unique containers with given or shared fields.
```

```{theorem} shared.typing.given_fragment
:status: draft
:uses: shared.typing.statements shared.typing.patterns given.typing.statements shared.embedding shared.correspondence

Restrict field declarations and types to `given` and omit give-share
expressions. The typing rules then agree with Given's rules, including its
unpacking extension. Embedding every runtime reference with mode `unique`
preserves and reflects statement transitions and completion in this fragment.

This extends the earlier correspondence, which covers only single-variable
bindings, to the machines with unpacking.
```
